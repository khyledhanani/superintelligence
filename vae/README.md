# VAE & Behavioral Embedding Analysis for LLM Injection Experiments

## Overview

This directory contains a VAE for maze level encoding/decoding and scripts to analyze how LLM-generated levels behave within the PLR buffer during ACCEL training. The central analysis is **t-SNE visualization of 257D behavioral embeddings** computed by the evolving trained agent on its buffer at each training timestep, colored by level provenance (organic ACCEL vs LLM-injected).

---

## 1. VAE model

**CluttrVAE** (`vae_model.py`) encodes maze levels as token sequences into a latent space. Supports 13x13 and 21x21 grids.

| Parameter | 13x13 | 21x21 |
|-----------|-------|-------|
| `vocab_size` | 170 | 442 |
| `seq_len` | 52 | 152 |
| `latent_dim` | 64 | 96 |
| `embed_dim` | 300 | 300 |
| `enc_lstm_dim` | 300 | 400 |
| `dec_lstm_dim` | 400 | 512 |

**Token format**: `[wall_indices (1-based, sorted, 0-padded), goal_idx, agent_idx]`. For 13x13: 50 wall slots + 2 = 52 tokens. For 21x21: 150 + 2 = 152.

**Checkpoints** (local copies): `/cs/student/project_msc/2025/csml/rhautier/vae_checkpoints/{13x13,21x21}/`

**GCS source** (bucket: `gs://ucl-ued-project-bucket`):

| Grid | GCS checkpoint | GCS config | Training run ID |
|------|---------------|------------|-----------------|
| 13x13 | `vae/runs/20260309_091933_lr5e-05_lat64_clutr_aligned_rw1000_beta10.0/checkpoints/checkpoint_500000.pkl` | `vae/runs/20260309_091933_lr5e-05_lat64_clutr_aligned_rw1000_beta10.0/config.yaml` | `clutr_aligned_rw1000_beta10.0` |

## 2. Behavioral embeddings (257D)

The core representation for all analysis. Captures **how the agent behaves** on a level, not its structure.

**Computation** (from `maze_plr.py:compute_insertion_embeddings()`):
1. Roll out the agent on a level for one episode
2. Mask timesteps after the first `done`
3. **256D**: mean LSTM hidden state over masked timesteps
4. **1D**: mean discrete action over masked timesteps
5. Concatenate → **257D embedding per level**

Two levels with similar embeddings = the agent exhibits similar internal representations and action patterns on both.

## 3. Injection experiment setup

An ACCEL agent was trained for 10k updates (warmstart). LLM-generated maze levels (and their wall-flip mutations) were then **injected** into the PLR buffer at various percentages, and training continued for another 10k updates.

**Injection percentages**: 5%, 10%, 15%, 20%, 25% of the 4000-level buffer replaced with LLM-lineage levels.

**Seeds**: 3 random seeds (0, 1, 2) per percentage = **15 training runs**.

**Provenance tracking**: Each buffer level is tagged with an `origins` value:
- **0** = organic (generated by ACCEL during training)
- **1** = LLM original seed (directly from LLM generation)
- **2** = LLM mutation descendant (wall-flip mutation of an LLM seed)

| **Buffer dumps** (every 250 updates) | `llm-exp/training/inject_llm_{pct}pct_seed{s}/buffer_dumps/inject_llm_{pct}pct_seed{s}/{s}/buffer_dump_{N}.npz` | Buffer state at update N |
| **Pre-computed embedding cache** | `llm-exp/embedding_caches/tsne_training_cache/emb_{pct}_s{seed}_t{timestep}.npz` | 257D embeddings (5 rollouts averaged) |
| **Warmstart agent** | `llm-exp/checkpoints/accel_sfl_baseline_13x13/0` | Pre-injection ACCEL checkpoint |
| **Mutation outputs** | `llm-exp/injection/` | Merged buffers, eligible pools |

**Checkpoint step ↔ update mapping**: `step = (updates / 250) - 1`. Examples: 250 updates → step 0, 1000 → step 3, 10000 → step 39.

**Available runs**: `inject_llm_{5,10,15,20,25}pct_seed{0,1,2}` (15 total).

### Buffer dump `.npz` format

| Key | Shape | Description |
|-----|-------|-------------|
| `tokens` | (size, 52) | Token encoding of each level |
| `scores` | (size,) | PLR learnability scores (SFL) |
| `origins` | (size,) | 0=organic ACCEL, 1=LLM original, 2=LLM mutation |
| `origin_ids` | (size,) | Deterministic hash per injected level |
| `ancestor_ids` | (size,) | Which LLM seed each descendant traces to |
| `embeddings` | (size, 257) | **Stale** — computed at insertion time, NOT by current agent |
| `size` | scalar | Number of active levels |
| `update_num` | scalar | Training update count |

**Important**: The `embeddings` field in buffer dumps is stale (from the agent at insertion time). For accurate analysis, use `plot_tsne_training_evolution.py` which recomputes embeddings from the current agent checkpoint.

### Embedding cache `.npz` format

| Key | Shape | Description |
|-----|-------|-------------|
| `embeddings` | (size, 257) | Fresh 257D embeddings (5-rollout average from current agent) |
| `origins` | (size,) | Provenance tags (same as buffer dump) |
| `scores` | (size,) | PLR scores |

## 5. t-SNE of buffer evolution during training

Two modes, two scripts. Both produce grids with rows = seeds/runs, columns = timesteps.

### 5a. LLM injection analysis (`plot_tsne_training_evolution.py`)

Tracks how injected LLM levels evolve within the PLR buffer during training. Supports both **behavioral** (agent rollout) and **structural** (env layout) embeddings.

**Modes**:
- `--mode behavioral` (default): 257D embeddings from agent rollouts. Requires GPU + agent checkpoints.
- `--mode structural`: 173D features from wall map + positions. CPU only, no checkpoints needed.

**What it does** (for each injection_pct × seed × timestep):
1. Downloads the **buffer dump** from GCS (+ agent checkpoint in behavioral mode)
2. Computes embeddings (behavioral: 5-rollout average; structural: token→feature conversion)
3. Fits **t-SNE independently per cell**
4. Plots colored by provenance: grey = organic ACCEL, green = LLM mutations, blue stars = LLM originals

**Output**: `vae/plots/tsne_training_evolution/tsne_{behav,env}_{pct}.png`

**Cache**: Defaults to `/cs/student/project_msc/2025/csml/rhautier/embedding_caches/injection_{behavioral,env}/`. **Adapt this path** if running on a different machine — use `--cache_dir` to override.

**GCS cache** (pre-computed, pull with `--cache_only`):
- `gs://ucl-ued-project-bucket/llm-exp/embedding_caches/injection_behavioral/`
- `gs://ucl-ued-project-bucket/llm-exp/embedding_caches/injection_env/`

```bash
# Behavioral — all pcts, GPU, auto-upload to GCS
python vae/plot_tsne_training_evolution.py --mode behavioral --upload_gcs

# Structural — all pcts, CPU only, auto-upload
python vae/plot_tsne_training_evolution.py --mode structural --upload_gcs

# Single pct, custom cache dir
python vae/plot_tsne_training_evolution.py \
    --inject_pct 10pct --mode structural \
    --cache_dir /your/path/here

# Plot from pre-computed cache only (no GPU, no GCS downloads)
python vae/plot_tsne_training_evolution.py --mode behavioral --cache_only

# Fewer timesteps / seeds
python vae/plot_tsne_training_evolution.py \
    --mode structural --timesteps 250,1000,5000,10000 --seeds 0,1

# 21x21 grids (structural mode)
python vae/plot_tsne_training_evolution.py --mode structural --grid_size 21
```

### 5b. Cross-run comparison (`plot_tsne_compare_runs.py` + `plot_tsne_compare_env.py`)

Compare buffer evolution across **different training methods** (e.g., ACCEL vs CMA-ES vs CMA-ES+LatentMut). Runs are defined in a YAML config file.

- `plot_tsne_compare_runs.py` — behavioral embeddings (257D, GPU)
- `plot_tsne_compare_env.py` — structural features (173D, CPU)

Both use the same YAML config format:

```yaml
# compare_example.yaml
title: "My Comparison"
color_by_origin: true       # color by provenance (DR/CMA-ES/mutation)
grid_size: 13               # for structural script
timesteps: [16000, 18000, 20000, 22000, 24000, 26000, 28000, 30000]

runs:
  - name: "Seed 0"
    gcs_prefix: accel/accel_sfl_13x13          # GCS path prefix
    run_id: accel_sfl_13x13                     # subdirectory name
    seed: 0
  - name: "Seed 1"
    gcs_prefix: accel/accel_sfl_13x13
    run_id: accel_sfl_13x13
    seed: 1
    # ... or use local paths:
    # checkpoint_dir: /path/to/checkpoints/run/seed/
    # buffer_dir: /path/to/buffer_dumps/
```

**Origin codes** (auto-detected per run):

| Code | LLM injection runs | CMA-ES runs |
|------|-------------------|-------------|
| 0 | Organic ACCEL | DR generation |
| 1 | LLM original seed | CMA-ES generation |
| 2 | LLM mutation descendant | DR-lineage mutation |
| 3 | — | CMA-ES-lineage mutation |

**Pre-built configs** for ACCEL vs CMA-ES comparison (3 seeds × 8 timesteps each):
- `compare_accel.yaml` — pure ACCEL baseline
- `compare_cmaes_accel.yaml` — CMA-ES generation + ACCEL wall-flip mutations
- `compare_cmaes_latent.yaml` — CMA-ES generation + VAE latent mutations

**Run all three** (behavioral + structural, auto-uploads to GCS):
```bash
bash vae/run_cmaes_comparison.sh
```

Or individually:
```bash
# Behavioral (GPU)
python vae/plot_tsne_compare_runs.py \
    --config vae/compare_accel.yaml \
    --cache_dir /cs/student/project_msc/2025/csml/rhautier/embedding_caches/cmaes_compare \
    --output vae/plots/tsne_accel.png

# Structural (CPU)
python vae/plot_tsne_compare_env.py \
    --config vae/compare_accel.yaml \
    --cache_dir /cs/student/project_msc/2025/csml/rhautier/embedding_caches/cmaes_compare_env \
    --output vae/plots/tsne_env_accel.png

# From cache (CPU)
python vae/plot_tsne_compare_runs.py --config vae/compare_accel.yaml --cache_only \
    --cache_dir /cs/student/project_msc/2025/csml/rhautier/embedding_caches/cmaes_compare
```

**Note**: All `--cache_dir` and `--local_data_root` paths default to `/cs/student/project_msc/2025/csml/rhautier/...` — **adapt these** to your local filesystem if running elsewhere.

**GCS cache locations**:
