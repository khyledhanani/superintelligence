<objective>
Patch both launch scripts for single-seed parallel execution and switch the LLM provider to
OpenRouter, then confirm all 3 ACCEL+LLM seeds are running on GPU nodes.

Purpose: The existing scripts run seeds 0-2 in a for-loop on one machine (sequential). For
50k steps with 3 seeds that would take ~3x longer than necessary. Parallel execution across
albacore/smew/canada requires one seed per invocation. The claude-code provider must be
replaced with openrouter before production runs to avoid subscription quota exhaustion
(~1200 LLM calls per 50k run).

Output: Two modified launch scripts (single-seed), updated llm/config.yaml (openrouter
provider), pre-flight check script, and 3 confirmed ACCEL+LLM training processes running
on GPU nodes.

Note on control condition: The locked decision (CONTEXT.md) is to reuse existing
JAXUED_LEARNABILITY accel-sfl runs as control — do NOT run launch_accel_only_control.sh.
The script is patched for completeness but its execution is deferred to Plan 04-02 only if
JAXUED_LEARNABILITY accel-sfl runs are found to be insufficient at analysis time.

Contingency (documented here, not a task): If gate accepts nothing by ~step 20k, lower
difficulty_threshold in llm/config.yaml from 0.6 to 0.4. Check WandB llm/acceptance_rate
after the first injection event (step 5000+). If acceptance_rate == 0.0, intervene
immediately.
</objective>
