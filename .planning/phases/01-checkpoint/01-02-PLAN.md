  <name>Task 1: Create LLMInjectionManager orchestrator class</name>
  <files>llm/injector.py</files>
  <action>
Create `llm/injector.py` containing the `LLMInjectionManager` class. This is the single orchestrator that encapsulates the full injection pipeline. The class must be stateless between injection events except for configuration and the MazeGenerator instance.

**Constructor: `__init__(self, config: LLMInjectionConfig, level_sampler: LevelSampler, eval_freq: int)`**
- Store config, level_sampler, eval_freq
- Initialize `BufferStatsExtractor(n_references=config.n_reference_mazes, strategy=config.reference_maze_strategy)`
- Initialize `MazeGenerator` using `GenerationConfig` populated from the LLMInjectionConfig (provider, model, config_path). Load generation config from `config.config_path` (YAML file) using the existing pattern in `llm/maze_generator.py`.
- Initialize `mutate_level = make_level_mutator_minimax(100)` for mutation amplification
- Initialize counters: `self.total_injected = 0`, `self.total_attempted = 0`

**Main method: `maybe_inject(self, runner_state: tuple, eval_step: int) -> tuple`**
- `runner_state` is `(rng, train_state)` -- same structure as in the training loop
- Compute `current_step = eval_step * self.eval_freq`
- If `not self.config.enabled`: return runner_state unchanged
- If `current_step < self.config.warmup_steps`: return unchanged
- If `eval_step % self.config.injection_interval != 0`: return unchanged (NOTE: injection_interval is in eval_steps, not raw steps. Per CONTEXT.md, the interval unit is steps, so convert: `steps_between_injections = self.config.injection_interval`, and check `current_step % steps_between_injections != 0`). Actually, re-reading CONTEXT.md: `injection_interval: int = 3000  # steps between injections`. The training loop counts in eval_steps. So the check should be: `if current_step < self.config.warmup_steps or current_step % self.config.injection_interval != 0: return runner_state`.
- Call `self._do_injection(runner_state)` and return the updated runner_state.

**Core pipeline: `_do_injection(self, runner_state) -> tuple`**
Orchestrates the full injection pipeline:

1. **Extract references:**
   ```python
   rng, train_state = runner_state
   sampler = train_state.sampler
   references = self.buffer_stats.extract_references(sampler)
   buffer_summary = self.buffer_stats.extract_buffer_summary(sampler)
   ```

2. **Build prompt and generate mazes:**
   ```python
   from llm.prompt_builder import build_generation_prompt
   prompt = build_generation_prompt(references=references, global_metrics=buffer_summary)
   ```
   Generate `self.config.n_raw` mazes by calling `self.generator.generate(references=references)` in a loop. Each call returns a `GenerationResult`. Collect all results.

3. **Validate generated mazes:**
   Create a `validate_llm_level(level: Level) -> tuple[bool, str]` method that checks:
   - `level.is_well_formatted()` -- basic format check
   - Border walls: all cells on row 0, row 12, col 0, col 12 should be walls (check `level.wall_map[0, :].all()`, etc.). NOTE: This is a soft check -- LLM mazes don't always have full border walls, and many valid mazes don't. Actually, per CONTEXT.md requirement: "border wall check". So implement it but make it a warning, not a hard reject. Actually, per the requirements doc INTG-02: "border wall check and BFS path length >5". So implement border wall check as a hard validation.
   - BFS path length: Run BFS from agent_pos to goal_pos on the wall_map. Path length must be > 5. Implement a simple numpy BFS (not JAX -- this runs Python-side). Return `(is_valid, reason_string)`.

   Filter generated levels through `validate_llm_level()`. Log rejected levels with rejection reason.

4. **Mutation amplification (if enabled):**
   For each validated seed level:
   - Generate `config.mutations_per_seed` wall-flip mutations using `make_level_mutator_minimax`. Since this is JAX-compiled, use `jax.vmap` over a batch of random keys with the seed level.
   - For each mutation, check solvability via BFS (numpy-side: convert wall_map to numpy, run BFS from agent_pos to goal_pos). Only keep solvable mutations.
   - Cap total mutations at `config.max_inject_per_event`.

5. **Score and inject into buffer:**
   Collect all accepted levels (seeds + surviving mutations) into a single batch, then insert once:
   - Assign maximum priority score to force immediate replay. Use the max of current buffer scores: `max_score = float(np.asarray(sampler["scores"][:int(np.asarray(sampler["size"]))]).max())`. Add a small epsilon to ensure they're highest priority.
   - **NOTE: `score_seeds_with_rollout` defaults to False in Phase 1. No policy rollout scoring is performed — all levels get max priority. Seed rollout scoring (Tier 1 from CONTEXT.md) is deferred to Phase 2 when AgentEvaluator is wired in.**
   - Stack all accepted Level objects into a batched Level pytree (use `jax.tree_util.tree_map(lambda *xs: jnp.stack(xs), *levels_list)`) and create a corresponding `jnp.array` of scores (all set to `max_score + epsilon`).
   - Insert the batch via `self.level_sampler.insert_batch(sampler, levels_batch, scores_batch)`. This returns `(new_sampler, inserted_indices)` in a single call. Do NOT loop with `level_sampler.insert()`.
   - Track `retained_count = int(jnp.sum(inserted_indices >= 0))` — the number of levels that were actually inserted (not rejected by the buffer's eviction policy). Compute `retained_rate = retained_count / total_attempted` for logging.
   - Update train_state: `train_state = train_state.replace(sampler=new_sampler)`
   - Return `(rng, train_state)`

6. **WandB logging:**
   After injection, call `wandb.log()` with:
   - `llm/injected_count`: total levels inserted this event (seeds + mutations)
   - `llm/seeds_generated`: number of raw LLM outputs attempted
   - `llm/seeds_valid`: number passing validation
   - `llm/mutations_generated`: total mutations attempted
   - `llm/mutations_solvable`: mutations passing solvability
   - `llm/acceptance_rate`: seeds_valid / seeds_generated
   - `llm/retained_rate`: retained_count / total_attempted (fraction of levels actually inserted into buffer, not evicted)
   - `llm/injection_time_seconds`: wall clock time for this injection event
   - `llm/total_injected`: cumulative count across all events
   - `llm/mutation_survival_rate`: mutations_solvable / mutations_generated (if amplification enabled)

**Important implementation details:**
- On any LLM API error (MazeGenerator.generate() raises or returns non-success result after all retries), raise an exception immediately. Per CONTEXT.md: "On API failure: crash training immediately". Do NOT catch and skip.
- All JAX array access must go through `np.asarray()` for Python-side operations.
- The `level_sampler.insert_batch()` call is a pure functional JAX operation. It returns `(new_sampler, inserted_indices)`. Use a single batch call, NOT a loop of `insert()` calls.
- Import `wandb` at the top level. If wandb is not initialized (unlikely in training), guard the log call.
- Use `time.time()` to measure injection latency.
- The BFS validation should be a standalone function `_bfs_path_length(wall_map_np, start, goal) -> int` that returns path length (or -1 if unsolvable). Use collections.deque for BFS.
