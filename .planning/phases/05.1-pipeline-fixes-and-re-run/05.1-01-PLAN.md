**Fix 1 — config.yml:**
Change `cma_restart_threshold: 0.01` to `cma_restart_threshold: 0.05`.
Leave all other config fields unchanged. The comment on that line should read:
`# restart CMA-ES when sigma < this fraction of sigma_init (was 0.01; 0.05 gives 3-5 restarts/20k)`

Target: sigma_init=0.5, threshold 0.05 means restart fires when sigma < 0.025 (5% of initial).
This yields approximately 3-5 IPOP restarts per 20k run instead of the 1 restart observed.

**Fix 2 — svcmaes_strategy.py:**
In the `tell()` method, after the line:
```python
        new_mean_i = new_particles[i]["es_state"].mean + repulsion[i]
```
Add a jnp.clip to clamp particle means to the approximate extent of the VAE training distribution:
```python
        new_mean_i = jnp.clip(new_mean_i, -3.0, 3.0)
```

This prevents Stein repulsion from accumulating unbounded drift over 5000+ steps.
The clamp radius 3.0 matches the unit normal prior of the VAE (valid latents are
approximately in [-3, 3]^64). The clamp is inserted immediately after the repulsion
addition and before the es_state.replace() call.

The full modified block (lines 231-234 area) becomes:
```python
    for i in range(N):
        new_mean_i = new_particles[i]["es_state"].mean + repulsion[i]
        new_mean_i = jnp.clip(new_mean_i, -3.0, 3.0)  # prevent latent drift (Phase 5.1 fix)
        updated_es_state = new_particles[i]["es_state"].replace(mean=new_mean_i)
        new_particles[i] = {**new_particles[i], "es_state": updated_es_state}
```

Do NOT change any other part of svcmaes_strategy.py.

Key fixes vs the original run_phase5_sequential.sh ACCEL block:
1. Add `--use_accel` flag (was missing — without it, the script runs as PLR not ACCEL)
2. Run as a standalone script invoked in a fresh tmux window (not chained to ES processes)
3. Unset XLA_FLAGS to avoid breaking JAX 0.5.3's automatic libdevice discovery
4. Add `--group phase5-comparison` so WandB groups correctly with the ES runs
5. Add `--checkpoint_save_interval 2000 --max_number_of_checkpoints 11 --eval_freq 500`
   to match the ES runs' checkpoint schedule (consistent evaluation points)

The script must NOT redirect ACCEL checkpoints to runs/ — maze_plr.py uses orbax format
and evaluate_checkpoints.py will be updated separately (Plan 04) to handle both formats.

Script content:
```bash
#!/bin/bash
# Phase 5.1: ACCEL baseline — standalone script.
# Run in a FRESH tmux window AFTER all ES runs have exited.
# cuSolver requires a clean CUDA context — do NOT chain after ES jobs.
#
# Usage:
#   bash scripts/run_phase5_accel_only.sh |& tee logs/phase5-accel.log
#
# Prerequisites:
#   - All three ES runs (CMA-ES, NS-ES, SV-CMA-ES) must have EXITED
#   - GPU must be free (check: nvidia-smi)
#   - No other JAX sessions on sideswipe/prowl

set -e

cd /cs/student/project_msc/2025/csml/gmaralla/superintelligence
unset XLA_FLAGS

PYTHON=/cs/student/project_msc/2025/csml/gmaralla/miniconda3/envs/jax_env/bin/python
SEED=42
UPDATES=20000
GROUP=phase5-comparison

mkdir -p logs

echo "=========================================="
echo "Phase 5.1: ACCEL baseline (standalone)"
echo "Seed=$SEED | Updates=$UPDATES | Group=$GROUP"
echo "Started: $(date)"
echo "GPU state before launch:"
nvidia-smi --query-gpu=name,memory.used,memory.total --format=csv,noheader
echo "=========================================="
echo ""

$PYTHON examples/maze_plr.py \
  --run_name phase5-accel \
  --project es-accel \
  --group $GROUP \
  --seed $SEED \
  --num_updates $UPDATES \
  --use_accel \
  --checkpoint_save_interval 2000 \
  --max_number_of_checkpoints 11 \
  --eval_freq 500

echo ""
echo "ACCEL done: $(date)"
echo "Checkpoints saved to: checkpoints/phase5-accel/$SEED/models/"
echo "WandB group: $GROUP"
```

Make the script executable: `chmod +x scripts/run_phase5_accel_only.sh`
